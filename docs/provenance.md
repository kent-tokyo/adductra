# Provenance

Implements `AGENTS.md` §12. Source: `src/model/provenance.rs`.

## What's tracked

```rust
pub struct Provenance {
    pub software_version: String,       // env!("CARGO_PKG_VERSION")
    pub rule_version: Option<String>,    // FragmentRule.version, when applicable
    pub database_version: Option<String>,
    pub source_citation: Option<String>, // FragmentRule.citation, when applicable
    pub algorithm_version: Option<String>, // e.g. "mass_evidence_evaluator_v1"
    pub parameters: BTreeMap<String, String>, // e.g. tolerance_ppm, rule_id
    pub generated_at: Option<String>,    // caller-supplied, never computed internally
}
```

Every `Evidence` carries its own `Provenance`; `AdductReport` carries one
for the run as a whole. Same input + same `Provenance` (versions,
parameters) must reproduce the same result — evidence evaluation is a
pure function of its inputs, which is also why `generated_at` is
caller-supplied rather than stamped internally with a wall-clock read:
that would make two runs of the identical input non-reproducing by
construction.

## Where it comes from in practice

- `MassEvidenceEvaluator` / `FragmentEvidenceEvaluator` stamp
  `algorithm_version` with their own evaluator name and record
  `tolerance_ppm` (or the matched rule's `id`) in `parameters`.
- `FragmentEvidenceEvaluator` additionally copies `rule_version` and
  `source_citation` straight from the [`FragmentRule`] that produced the
  evidence (`src/evidence/fragment.rs::rule_provenance`) — so a caller
  can always trace a diagnostic-fragment match back to the literature
  rule and its version, not just to "the fragment evaluator."
- `AdductCandidate::provenance` and `Observation` metadata are supplied
  by the caller (`EvidenceSource::UserProvided` / `Experimental`), not
  generated by Adductra.

## Rule versioning

`FragmentRule.version` (`rules/dna_adduct_fragments.json`) is a plain
semver-ish string bumped by hand when a rule's expected value or
tolerance changes. There is no rule-file schema migration machinery in
v0.1 — not needed until the rule set is large enough to need one
(`AGENTS.md` §24: don't over-optimize before there's a measured need).
